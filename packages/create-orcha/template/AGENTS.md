# Playground development guide

This is a dependency-light local interface for Orcha. Keep the browser
framework-free and the server bound to localhost.

## Architecture

- `orcha/` contains registered agent source.
- `src/server.ts` owns Orcha and exposes local API routes.
- `public/` contains static HTML, CSS, and JavaScript.
- `.orcha/sessions/` is the default Node JSONL storage directory and must not
  be committed. Application code must access sessions through agent methods,
  never through storage files.

The execution endpoint streams newline-delimited JSON. Preserve the sequence:
streaming snapshots, final result, then asynchronous evaluations. Client action
results must be submitted with the exact returned `callId`.

Use the complete Orcha `AGENTS.md` generated by `orcha init` as the source of
truth for agent configuration, actions, skills, tests, evaluations, and JSONL
event schemas.

## Constraints

- Do not add a frontend framework for basic interface work.
- Do not expose provider credentials or action source to the browser.
- Do not allow arbitrary filesystem paths through API routes.
- Validate session ownership before serving raw logs.
- Keep provider calls and filesystem access in the Node server.
- Keep generated projects understandable without special infrastructure.
