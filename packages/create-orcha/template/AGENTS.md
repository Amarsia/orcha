# Orcha project guide

This project uses Orcha's built-in local playground. Application-specific
frontend or server code is not required.

## Architecture

- `orcha/` contains registered agent source.
- `.orcha/sessions/` is the default Node JSONL storage directory and must not
  be committed.
- `npm run dev` starts `orcha playground`, which watches `orcha/**`.
- `npm run build` creates `.orcha/dist/bundle.js` and
  `.orcha/dist/manifest.json`; it does not include the playground React
  application.

When another tool packages an unbundled production application, explicitly
include `.orcha/dist/**`. A successful `orcha build` does not guarantee that a
later packager copied generated files. Inspect the final ZIP or container and
confirm that `.orcha/dist/manifest.json` is present.

Use the complete Orcha `AGENTS.md` generated by `orcha init` as the source of
truth for agent configuration, actions, skills, tests, evaluations, and JSONL
event schemas.

Provider credentials belong in `.env`. The standalone Orcha CLI loads that
file without overriding values already present in the process environment.
