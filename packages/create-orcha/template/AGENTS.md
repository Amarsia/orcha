# Orcha project guide

This project uses Orcha's built-in local playground. Application-specific
frontend or server code is not required.

## Architecture

- `orcha/` contains registered agent source.
- `.orcha/sessions/` is the default Node JSONL storage directory and must not
  be committed.
- `npm run dev` starts `orchajs playground`, which watches `orcha/**`.
- `npm run build` creates `.orcha/dist/bundle.js` and
  `.orcha/dist/manifest.json`; it does not include the playground React
  application.

When another tool packages an unbundled production application, explicitly
include `.orcha/dist/**`. A successful `orchajs build` does not guarantee that a
later packager copied generated files. Inspect the final ZIP or container and
confirm that `.orcha/dist/manifest.json` is present.

Use the complete Orcha `AGENTS.md` generated by `orchajs init` as the source of
truth for agent configuration, actions, skills, tests, evaluations, and JSONL
event schemas.

Direct-provider credentials belong in `.env`. Projects using
`amarsia.inference: true` need only `amarsia.key`; the standalone Orcha CLI
loads environment files without overriding values already in the process.
`storage: { strategy: "cloud" }` is local-first and uses the same project key.
Set `telemetry: { otel: true }` to use the application's global OpenTelemetry
provider, or pass `telemetry: { otel: { endpoint, headers? } }` to send
privacy-safe run traces directly to an OTLP/HTTP collector. Spans follow the
OpenTelemetry GenAI Semantic Conventions. Orcha telemetry never includes
prompts, responses, action arguments, or action outputs. Subagents share their
root agent's trace; `orcha.close()` marks active runs interrupted.
